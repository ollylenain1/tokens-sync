# Compatibility and known limitations

The current implementation is ready for local development testing. A production rollout still requires the live acceptance checklist in `docs/TESTING.md` on your repositories, Figma plan and installed fonts. This is an independent plugin, not an official Tokens Studio product.

## Input and providers

- GitHub.com / GitHub Enterprise Server: REST API, read-only fine-grained PAT with selected-repository **Contents: read**. Public repositories may work without a token. Organisation SSO may require authorisation. Classic tokens can work but may grant broader access.
- GitLab.com / self-managed GitLab: project numeric ID or nested namespace/project path; project-scoped **read_api** is recommended because this implementation uses tree and commit APIs as well as file reads. `read_repository` covers the file API but is not the general REST permission for the full workflow.
- Enter a real branch, tag or supported commit ref. Branch discovery, OAuth, device login, SSH, interactive SSO and writeback are not implemented. HTTPS, provider reachability and CORS must permit requests from Figma’s iframe. Private CAs and blocked VPN endpoints need configuration outside the plugin.
- A directory uses relative `.json` file paths as token set names, excluding `$themes.json` and `$metadata.json`. Point at the token directory, not a whole repository full of unrelated package JSON. Symlinks/submodules are not followed. Files without `.json` are ignored.
- A single file with `$themes`/`$metadata` is treated as a named-set bundle. Without these markers it defaults to one token tree; choose **Tokens Studio bundle** explicitly for metadata-free bundles. Sibling theme/metadata JSON is read when present. No JSON5/comments/trailing commas or Git LFS pointer resolution.
- Uses `$metadata.tokenSetOrder`; missing metadata falls back to deterministic file/key order with a warning. Source sets are fallback definitions, enabled sets override them, later enabled sets win, disabled sets are excluded. No implicit Cartesian product across independently selected theme groups.
- No themes: one collection per set with one Default mode. References across those independent default collections require an explicit theme configuration; missing references are reported.
- Ungrouped themes use their own theme name as the collection name, matching the public Tokens Studio attachment implementation.

| ----------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Color                                                                         | COLOR variable; optional solid paint style. CSS colors via Color.js; structured DTCG sRGB only. Out-of-gamut values rejected.                                                                                                                                          |
| Dimension, spacing, sizing, border width/radius, font size, paragraph metrics | FLOAT, accepting unitless numbers, px and rem. Configurable rem base, default 16 px.                                                                                                                                                                                   |

No calc/min/max/clamp, functions, em/vw/vh or context-dependent percentages.                                                                                      |
| Boolean                                                                       | BOOLEAN; actual JSON true/false only.                                                                                                                                                                                                                                  |
| String/text, font family                                                      | STRING; no implicit conversion of arrays or objects.                                                                                                                                                                                                                   |
| Font weight                                                                   | Numeric weights → FLOAT; native style names → STRING. Numeric typography weights map to standard named installed weights, not arbitrary variable-font axes. Missing/ambiguous fonts block export.                                                                      |
| Opacity                                                                       | FLOAT 0–1; percentage input normalized.                                                                                                                                                                                                                                |
| Line height / letter spacing                                                  | Scalar px/unitless values → FLOAT. Percentages are preserved inside text styles, not exported as contextless float bindings. DTCG typography numeric line height is a multiplier; legacy numeric line height is pixel-based.                                           |
| Typography                                                                    | Text style with exact installed family/style, font size, line height, letter spacing, paragraph spacing/indent, case and decoration. No silent font fallback. Unknown properties skip the entire style.                                                                |

Blur is nonnegative; spread may be negative.                                                                                |
| blur / layerBlur / backgroundBlur                                             | Effect style; these explicit token types are a **Blueprint extension**, not a claim that Tokens Studio defines a dedicated blur token type. Plain dimension tokens remain variables because their intended blur context is unknown.                                    |
| CSS linear gradient color                                                     | Paint style; explicit deg angle, at least two explicitly positioned percentage stops, ordered 0–100%. Stop color aliases preserved when supported. Geometry uses normalized square bounds; arbitrary consumer aspect ratios cannot reproduce all CSS sizing semantics. |
| CSS radial gradient color                                                     | Centered circle/ellipse subset; no explicit radii/positions, repeating gradients or color interpolation methods. Circle is disclosed as normalized geometry that becomes elliptical on non-square consumers.                                                           |
| DTCG gradient                                                                 | Stop array converted to a horizontal linear paint with a warning because the DTCG array does not supply geometry.                                                                                                                                                      |
| Border                                                                        | Three variables (color, width, stroke-style string), with a partial/composed-output notice. No native border style or automatic layer application. Complex stroke-style objects rejected.                                                                              |
| Multi-value radius/spacing                                                    | Two-to-four-value shorthand becomes four named scalar variables with disclosure; references in shorthand are resolved to literals. No CSS slash radius syntax.                                                                                                         |
| Composition, assets, duration, cubicBezier, transition, unsupported types     | Reported and skipped. No misleading generic string/style conversion.                                                                                                                                                                                                   |

Legacy `type/value` and DTCG `$type/$value/$description`, group `$type` inheritance and curly-brace token aliases are supported. DTCG `$extends`, JSON Pointer `$ref`, `$root` tokens and external resolver documents are not implemented. Tokens Studio color modifiers are rejected rather than ignored. Token-path normalization changes dots to Figma slash hierarchy; colliding normalized paths block the preview.

## Styles, themes and bindings

Linked styles share a group-qualified target only if all bound structure and unbound values agree across selected themes. Otherwise each theme gets its own literal style. This prevents one theme from overwriting another and avoids pretending native styles have modes.

Theme-specific naming enforces `{group}`, `{theme}` and `{token}` identity boundaries. Linked style names use `Linked`. If a token changes between shared and theme-specific representations, the previous styles remain preserved and the new strategy may create additional targets. Source style references are used when compatible; conflicting shared mappings require a choice.

Text bindings cover compatible family/style strings, font size, pixel line height/letter spacing and paragraph metrics. Numeric font weight is resolved to an installed style rather than bound automatically. Effect bindings cover color, blur radius, spread and offsets. Solid paint and gradient stop color references use the documented native bindings. Opacity multiplication and arithmetic cannot be represented as variable expressions and remain literals. A reference-only set does not create a variable; such references are inlined unless a unique compatible exported variable exists in another selected collection.

Cross-collection aliases bind to the unique exported variable with the referenced path, compatible type, and matching source set in any mode. The alias follows the active mode of the target collection. If several collections qualify, Blueprint keeps the resolved literal. Styles-only linked export requires existing variables to match the requested source values; otherwise enable variable sync or use theme-specific styles.

Local style bindings are preserved by default, including when they intentionally override a repository literal. Incompatible bindings or removal of their target property require review. Existing node bindings remain untouched; no scene graph is scanned.

## Mapping, extensions and recovery

- Existing Tokens Studio metadata is read and never rewritten. Both IDs and keys are validated against local objects, types and collection membership. No assumption is made that styles of every kind have source mapping metadata.
- No name guessing across unrelated collections. Multiple matches, changed types, missing Blueprint registry targets and potential renames require a designer choice. Tokens Studio hints absent from the destination file fall back to normal name matching or creation. Hints that resolve to incompatible local objects require review. Duplicate or conflicting mode names must be corrected in Figma/source.
- Source metadata does not universally identify its originating file. A bare ID with a different current name cannot authorize a rename; a validated key or plugin-owned registry can. Unavailable remote library mappings are not automatically imported.
- The simplified UI does not expose extended collections. The underlying adapter retains tested support using the documented `extend()` and inherited mode values. Enterprise entitlement has no general read-only probe: API presence is shown, creation is tried only after Sync, and failure is explained. This version extends local parents and overrides existing inherited variables only. It does not create extension-local variables, create parent modes, reparent collections, import remote parents or clear source-removed overrides.
- No automatic deletion or destructive cleanup. Missing-source rows can also mean a token was excluded by filters. Inspect and remove unwanted objects manually in Figma if appropriate.
- Figma writes are not atomic. A cancelled/failed operation can leave successfully created objects and partial values. Mappings are checkpointed so retries update those targets. Style restoration is best-effort; immediate Figma Undo is the complete-session recovery path.
- There is no backend, background service, telemetry, publishing, repository modification or credential sharing. Watch and automatic application are not available. Fetch and send are manual.
